ToothBuddy UI/UX 对标报告

2026-07-01 · 基于美区 App Store 头部 + 健康类 + Duolingo 赛道调研 · 对照现有代码逐条给建议

一句话结论

地基不差，问题不在"配色/组件"，而在它不会动、不会反应、也不会奖励你。Duolingo/Finch 这类 app 的"贵气"几乎全来自一个会呼吸、会对你的操作做表情的吉祥物，加上"每个有意义的事件都同时命中视觉+触感+声音"的多通道反馈。你们现在吉祥物是一帧静态 Canvas 图、庆祝只有"文字+方块彩带"、里程碑没有触感——这就是"naive"的来源，而不是颜色土。

如果只做三件事（按性价比）：

  1. 让 Buddy 活过来——手搓一个 3–5 状态的 SwiftUI 吉祥物（待机呼吸 / 刷牙鼓励 / 胜利跳），在 session、胜利、空状态复用。这是把"naive→有灵魂"的最大杠杆。
  2. 给每个关键事件加多通道反馈——.sensoryFeedback 触感 + 声音 + 角色反应，同时发生（换区、达标 30s/60s/2min、结束）。半天工作量，感受质变。
  3. 重做 session 计时区——把纯文字计时器换成"环形 + 阶段刻度 + 数字滚动 + 达标庆祝"，这是产品核心屏，也是现在最敷衍的地方。

1 · 现状诊断：它为什么显得 naive

先说明白：你们的设计系统本身是及格线以上的。DuoTheme.swift 里色板/字体/深度阴影都成体系（Nunito 全字重、2pt ink 描边、4pt 实心投影、14pt 圆角），BrushGameOverlay.swift 的彩带还是带重力的物理模拟。所以问题不是"重做设计系统"，而是几个具体的、能点名的弱点：

弱点位置问题
吉祥物是静态图，从不反应DuoCharacters.swift:49–97 (BuddyView)、392–466 (FoamView)Buddy/Brush/Plaque/Foam 全是一帧 Canvas 渲染，不眨眼、不弹跳、不对换区/胜利做任何表情。Duolingo 的灵魂恰恰是"角色会反应"。
计时器是纯文本、还用系统字体BrushView.swift:308–313.system(size:48) 而非 Nunito（品牌断层）；除了 .numericText() 没有任何仪式感，达标里程碑无高光/弹跳。
胜利庆祝是"文字 + sparkles 图标"BrushGameOverlay.swift:349–359只有一个静态 SF Symbol + "All sparkly clean!" 文字框；没有角色登场、没有触感、没触发已有的 SoundManager。
换区反馈只有正弦脉冲圈BrushGameOverlay.swift:218–228换刷牙区只有一个 sin 波脉动圆环，无弹跳、无角色手势、无触感。机械感。
空状态：Buddy 半透明、无动画HistoryView.swift:113–121Buddy 压到 0.55 透明度反而显得"蔫了"，没有邀请感。
图标全是 SF Symbols（~51 处）全仓 Image(systemName:)牙齿用系统 mouth.fill、庆祝用 sparkles——全是 Apple 默认件，没有自己的视觉语言，"现成货"味重。
Settings 是裸的系统 FormSettingsView.swift 全文没套任何 Duo 组件（无描边/无深度），和 app 其余部分视觉断层，像半成品。
彩带是简单方块BrushGameOverlay.swift:273–279物理不错，但只有圆角方块，无旋转、无多形状（星/心/丝带）、无辉光。
结果卡角色静止、星级纯文本BrushView.swift:555–630 (DoneResultSheet)FoamView 一登场就是"已经开心"的定格，不是从中性 morph 到庆祝；星级只是文字徽章，无逐颗弹入。

我的判断：这些弱点有一个共同根因——缺少"状态驱动的动画"。现在的动画都是"进场时播一次"的装饰（onboarding 的 stagger 其实做得不错），但没有"app 状态变了 → 角色/UI 做出反应"这一层。Duolingo、Finch、Balatro 的高级感全在这一层。

2 · ⚠ 一个绕不开的技术约束（.swiftpm）

必读 · 影响方案选型

你们是 .swiftpm（Swift Playground App）格式，它不允许带 binaryTarget 的 SPM 依赖。业界做 Duolingo 式吉祥物的两大工具——Rive（rive-ios）和 Lottie（lottie-spm）——都是预编译 XCFramework 二进制包，在 .swiftpm 里直接用不了（Swift Forums 官方确认）。

这不是小事：几乎所有"怎么做 Duolingo 吉祥物"的教程都让你上 Rive。你们不能直接抄。

你们的岔路口（需要你拍板）：

  • 路线①：留在 .swiftpm，手搓 SwiftUI 吉祥物。用分层视图 + .phaseAnimator/.keyframeAnimator 做 3–5 个离散表情状态。上限比 Rive 低（没有骨骼/状态混合），但零依赖、够用、且现在就能做。我推荐先走这条——你们只需要"待机呼吸 / 鼓励 / 胜利"几个状态，手搓完全 hold 得住。
  • 路线②：把工程转成 .xcodeproj，接 Rive。能拿到真正的状态机吉祥物（表情平滑混合、可被输入实时驱动），天花板高很多，但要脱离 Swift Playground 生态、加构建复杂度。等你们确定要长期投产品、且吉祥物要成为核心资产时再转。
好消息

纯 SwiftUI 的现代动效 API 全部可用、零依赖：spring 预设（.snappy/.bouncy/.smooth）、.phaseAnimator、.keyframeAnimator、.symbolEffect（SF Symbol 弹跳/旋转/呼吸）、.contentTransition(.numericText())（数字滚动）、.sensoryFeedback（触感）、TimelineView + Canvas（自定义粒子/环，你们已经在用）。ConfettiSwiftUI（纯源码、非二进制）也能进 .swiftpm。
换句话说：下面 90% 的建议在 .swiftpm 里就能落地，不用转工程。

3 · "premium vs naive" 的可观察差异（对照清单）

调研里最有用的一份，是把"高级 vs 业余"落到可观察、可检查的具体差异，而不是玄学。拿这张表对着你们的屏自查：

维度naive（现在容易踩的）premium（目标）
动画全 easeInOut、时长都 300ms、进场播一次的装饰动画spring 物理、按动作语义调 damping、staggered 有序进场、状态驱动的反应
反馈只有视觉，或只有声音每个有意义事件同时命中 ≥2 个感官通道（视觉+触感 / 视觉+声音），触感落在动画峰值而非按下瞬间
颜色5+ 颜色到处装饰用，无语义映射2–3 个语义色，严格绑定含义（Balatro：蓝=基础、红=倍率；WHOOP：绿/黄/红=恢复度）
图标系统 SF Symbol 到处用、混搭系统件用在"隐形时刻"（键盘/选择器），品牌时刻用自定义件（庆祝/空状态/成就）
排版3+ 字体、正文无字重变化、全大写乱用≤2 字体、display 与 body 有强字重对比、行高 1.4–1.6
间距随手定、贴边、密8pt 栅格纪律、留白慷慨、主操作在拇指区
组件整屏系统默认控件有一套设计系统（同一套 spacing/时长/圆角 token），随机开三屏没有一个值是"目测的"

你们已经满足"设计系统"和"颜色纪律"两条（Duo token 到位）。差的是动画、反馈、图标这三条——正好对上第 1 节的诊断。

4 · 逐条建议：参考谁 → 对应你们哪 → 怎么改

每条都点名一个真实 app、指到你们具体文件、给出 SwiftUI 落地手段和工作量估。🟢 快<1h   🟡 中半天–1天   🔴 大多天/需决策

A. 会呼吸、会反应的吉祥物 🔴 大

Duolingo · DuoFinchHeadspace mood-blobChomper Chums
参考Finch 的核心洞察最适合你们：吉祥物的样子本身就是数据可视化——不显示"今天刷得好"这个数字，而是让小鸟蹦跳、发光。Duolingo 的 Duo 有一整套情绪状态（开心/震惊/难过/头炸），由 session 表现驱动，不是导航切换。Headspace 的角色永远在 2–4 秒的呼吸循环里"待机"，从不定格。
现状你们 DuoCharacters.swift 的 5 个角色全是定格 Canvas 图。这是"naive"的最大单一来源。
改法手搓一个状态驱动的 BuddyView（.swiftpm 内可行，见约束）。最少三态：
• idle——2–3 秒呼吸循环（整体缩放 1.0↔1.03 + 眼睛偶尔眨），用 .phaseAnimator 常驻；
• cheer——刷牙中每达标一个区/里程碑，弹跳 + 咧嘴 + 眼睛变 ^^；
• celebrate——结束达标，跳起 + 星星环绕。
把眼睛/嘴/身体拆成独立图层，各自绑一个 @State 相位。关键改变：Buddy 要出现在 session 屏里陪刷（现在 session 里根本没有它），而不只是 header 装饰。
取舍先做 idle+celebrate 两态就能拿到 80% 的"活过来"效果，1–2 天。全套表情再迭代。若哪天决定上 Rive → 走约束里的路线②。

B. 多通道反馈（juice）🟡 中

Balatro（ADA 2025）DuolingoApple Activity Rings
参考Balatro 是"juice"教科书：每个得分事件同时上五层反馈——卡片滑动、数字滚动、按事件量级的屏幕抖动、配色匹配的粒子、音高递进。核心洞察：屏幕抖动让你在看清数字之前先"体感"到分数量级。Duolingo 叫这个 multi-modal feedback——每次答对同时触发角色反应+啁啾声+轻触感，少任何一个通道就"薄"了。业界经验：触感要落在动画弹到位的峰值，不是按下瞬间。
现状换区（218–228）只有视觉脉冲；胜利（349–359）只有视觉，没调 SoundManager，没触感；里程碑没有任何反馈。
改法给这几个事件各配"视觉+触感+声音"三件套：
• 换区：环形弹一下（spring 而非 sin）+ .sensoryFeedback(.selection) + 已有 SoundManager.zoneChanged()；
• 达标 30/60/120s：数字弹一下 + .impact(weight:.light) + Buddy cheer；
• 结束达标：.sensoryFeedback(.success) + 彩带 + Buddy celebrate + 音效。
用 iOS 17+ 的 .sensoryFeedback(_, trigger:)，比老的 UIImpactFeedbackGenerator 干净。
取舍投入产出比最高的一档。API 全是原生、零依赖，半天能铺完主要事件。注意尊重你们已有的 Reduce Motion 处理。

C. Session 屏（核心，最该重做）🟡 中

Zero（禁食计时环）Headspace（呼吸）Pokémon Smile（AR 分区）Brush DJ
参考Zero 的禁食环最值得抄：环随时间填充，且把"脂肪燃烧/生酮/自噬"标成环上的阶段刻度——进度不只是时间，而是生物学意义。→ 你们可以把 2 分钟标成"斑块松动 → 达到 ADA 推荐"的阶段。Headspace 的播放键本身像肺一样一呼一吸，给出节奏而不需要文字。Pokémon Smile（和你们最像）：前置摄像头当镜子，角落象限图指示刷哪块，看向别处计时暂停，全程无文字指示。
现状计时器是 48pt 纯文本（BrushView.swift:308–313），还用系统字体；换区只有脉冲圈。这是产品核心屏，却是现在最敷衍的地方。
改法用你们已在用的 TimelineView + Canvas 画一个进度环替代纯文本：环上标 30s/60s/120s 阶段刻度，达标刻度点亮 + 弹一下；中心数字保留 .numericText() 但换 Nunito；Buddy 蹲在环下方陪刷（见 A）。达标 2min 时环完成 + 庆祝。
取舍Canvas 环你们已有技术储备，不难。这屏一改，整个产品"核心体验"的档次直接上去。

D. 单一权威分数 + 进度可视化 🟡 中

Apple Activity RingsWHOOPOura（2025 改版）BetterMouth · MouthScore
参考WHOOP：把多信号压成一个权威数字（0–100），首屏一眼回答"今天怎样"，图表藏在下一层（三级渐进披露）。Activity Rings：未闭合的环靠"闭环强迫症"驱动，完成时 sparkle 粒子庆祝。Oura 新版 Today 用"头条新闻"模型——只推此刻最关键的一条。直接竞品 BetterMouth 已经有 0–100 的 MouthScore。
现状你们 HistoryView 有 level/streak/习惯曲线/成就，信息不少但没有一个统领性的数字或环让人一眼看懂"我刷得好不好"。
改法产品你们已经在测"刷牙质量"了——把它做成首屏一个大的质量分环（本次 session 分 + 今日/本周趋势），颜色走绿/黄/红语义。History 首条 = 此刻最该看的一条，其余下沉。
取舍这条一半是产品决策一半是 UI。若"质量分"算法还没稳，先别急着把它做成核心数字。

E. 庆祝与 streak 的"分级" 🟡 中

Duolingo（streak 火焰进化）Streaks（ADA 2016）Finch（可选 streak）
参考Duolingo 的关键原则是 proportional celebration——小胜利小彩带，大里程碑全屏；streak 图标会随天数进化（气球→凤凰→角色变身），30 天的火焰明显比 3 天的壮观。Finch 提供"streak freeze"保护和 4 档难度，避免破功即弃坑（这是伦理安全阀，现代实现几乎都有）。
现状庆祝是固定的一个文字框（349–359）；streak 卡是静态展示，无"越长越壮观"的视觉升级。
改法庆祝按量级分级：达标最低线 vs 满 2min vs 破纪录，彩带数量/角色动作/音效强度递增（你们 DoneResultSheet 已有 metMinimum 分支，扩成 3 档）。streak 火焰图标按天数换梯度（自定义件，见 F）。加 streak freeze 更人性。

F. 图标与插画体系 🟡 中

Duolingo（形状语言）Habitica（统一图标宇宙）claymorphism 趋势
参考Duolingo 的形状语言有明文规则：最少必要细节、先看剪影、夸张到接近漫画、全部由圆角矩形/圆/三角构成、无尖角、白色留白当画框。Habitica：选定一个图标隐喻宇宙，所有东西都在里面建（统一 2px 描边 + 平涂 + 轻阴影）。2026 图标趋势里 claymorphism（软糯膨胀形状、柔和阴影、类粉彩）特别适合刷牙这种"亲切、低压力、玩具感"的品类。
现状~51 处 Image(systemName:)，牙齿用系统 mouth.fill，全是 Apple 默认件，"现成货"味。
改法分两步、别一步到位：
1）先把 SF Symbols 用到位——.hierarchical/.palette 渲染模式 + .symbolEffect(.bounce) 点按弹跳（🟢 快，你们 TipsView 已经在用 hierarchical，铺开即可）；
2）只给"品牌时刻"做自定义件——牙齿、streak 火焰、成就徽章、货币，用统一 claymorphism 风格（PDF 矢量资源进 asset catalog，或自定义 SF Symbol 走 SF Symbols app 的 "Duplicate as Custom Symbol"）。键盘/选择器这种隐形处继续用系统件。
取舍自定义件需要画（或找人画），是唯一"要美术产能"的一条。但 claymorphism 门槛不高，一套核心 8–10 个件即可覆盖品牌时刻。

G. Kid / Adult：整套视觉切换，不只是换色 🔴 大

Pokémon Smile / Chomper Chums（kid）Oral-B / Sonicare（adult）Headspace / Zero（adult 氛围）Finch（跨龄）
参考儿童向和成人向是两套语言：Pokémon Smile 全 AR、卡通细菌当敌人、收集奖励、无文字、声音重；Oral-B 成人 app 是覆盖率地图 + 数字评分 + HealthKit，零角色。跨龄的 Finch 靠"照顾一个你命名的宠物"这个年龄中性的隐喻打通两端，视觉语言保持一致，只是任务类型不同。
现状你们 pivot 后把 kid/adult 改成了 Settings 开关（好决策），角色里也有 WisdomView（戴眼镜的臼齿，成人向）。但切换目前更多是"开关功能"，视觉语言没有整套切换。
改法让开关切换整套视觉基调：kid = 角色优先（Buddy 大、蹦跳多、音效多、session 不显数字）；adult = 氛围克制（Headspace/Zero 式安静计时环 + 结束后 WHOOP 式分数卡 + 可分享记录）。你们 pivot 记忆里"可验证记录给牙医看"的价值链，正好落在 adult 模式的"分数卡 + 记录"上。
取舍范围大、且和产品策略强绑定。建议排在 A/B/C 之后——先让单一模式够好，再分叉。

H. 排版 / 间距 / 颜色纪律 🟢 快

Duolingo（Feather + DIN）系统 SF Pro + SF Rounded
参考Duolingo 的字体规则：display 字体（Feather）永远是 body 字体（DIN Rounded）的 ~150% 大小，保证展示型主导。原则是吉祥物→字形→整体性格是一条线。间距上 premium 的共性是 8pt 栅格 + 慷慨留白（实测扫读快 20%+）。
现状Nunito 全字重体系本身很好（相当于你们的 Feather）。主要漏洞：计时器用了系统字体破坏一致性（见 I）；间距是 12–18/8–14 的手调值，没有明文 8pt 栅格 token。
改法在 DuoTheme 里补一个 spacing scale token（4/8/12/16/24…）并逐步替换手调值；确认所有大标题走 Nunito ExtraBold、正文走 Regular/SemiBold，字重对比拉开。低风险、纯收敛。

I. 一致性补洞 🟢 快

现状两个明显断层：SettingsView.swift 是裸系统 Form（无 Duo 组件）；计时器用 .system 字体而非 Nunito。
改法Settings 套上 DuoCard/自定义行样式，让它和 app 其余部分一致（"随机开三屏没有一个值是目测的"那条自查）。计时器换回 Nunito。都是纯收敛的低风险活。
取舍不性感但显脏。放进 quick-win 批次顺手做掉。

J. iOS 26 Liquid Glass（可选，按受众定）🟡 中

Moonlitt（ADA 2026 交互奖）Apple 系统
参考iOS 26（2025-06）的 Liquid Glass 是 2013 以来最大视觉改版：导航层用实时折射的半透明材质，滚动时 tab bar 收缩把焦点让给内容。ADA 2026 交互奖 Moonlitt 就是因为 Liquid Glass 用得好——chrome 在你用的时候消失。SwiftUI API：.glassEffect()、GlassEffectContainer。铁律：文字永远放实心层，不要直接压在玻璃上；别嵌套玻璃、别用在可滚动列表。
现状你们是自定义 tab bar（ContentView），没上 Liquid Glass。
改法可选。若目标是"最新原生质感"，可给 tab bar / header 的 chrome 上 .glassEffect()。但这跟你们 Duolingo 的"chunky 实心描边"美学其实有张力——玻璃是冷、透、极简，Duo 是暖、实、厚。我的判断：别为了追新而混搭，除非你们想整体往"更成人、更系统原生"的方向调。先把 A–C 做好更重要。

5 · 分阶段行动清单

按"性价比 / 依赖关系"排，不是按章节顺序。

🟢 第一批 · Quick wins（约 1 天，纯原生、零依赖、零决策）

  • spring 化：把关键交互的 .easeInOut 换成 .snappy/.bouncy（30 分钟，感受立变）。
  • 触感铺开：给换区/达标/结束加 .sensoryFeedback（B 的一部分）。
  • SF Symbol 用到位：.symbolEffect(.bounce) 点按反馈 + 统一渲染模式（F 第 1 步）。
  • 补一致性洞：计时器换 Nunito；Settings 套 Duo 组件（I）。
  • spacing token：DuoTheme 加 8pt 栅格（H）。

🟡 第二批 · 核心体验升级（约 1 周）

  • 吉祥物活起来（A）：先做 idle+celebrate 两态，塞进 session 屏和空状态。
  • Session 计时环（C）：Canvas 进度环 + 阶段刻度 + 达标点亮，替换纯文本计时器。
  • 多通道反馈补全（B）：三件套铺到所有关键事件，触感落在动画峰值。
  • 庆祝分级（E）：DoneResultSheet 扩成 3 档 proportional celebration。

🔴 第三批 · 需决策 / 要美术产能 / 大范围

  • 自定义图标集（F 第 2 步）：一套 claymorphism 品牌件（牙齿/火焰/徽章），要画。
  • 单一质量分 + 进度环（D）：等"质量分"算法稳了再做核心化。
  • Kid/Adult 整套视觉切换（G）：跟产品策略强绑，排在单模式够好之后。
  • 是否转 .xcodeproj 上 Rive（约束路线②）：只有当吉祥物要成为核心资产、手搓够不着时才考虑。
  • Liquid Glass（J）：可选，且和现有美学有张力，别为追新而混搭。
建议起点

先做第一批 quick wins——一天之内你就能明显感到 app "活"了，几乎零风险；然后集中火力做第二批的 A（吉祥物）+ C（计时环），这两个是把"naive"甩掉的主战场。第三批等你对方向拍板后再排。
另外提醒：这些视觉改动模拟器多半看不全（智能镜相机预览、分区高亮都要真机），跟你们 PROGRESS 里"真机 smoke 是最大的门"是同一件事——做完动效最好一起真机验。
