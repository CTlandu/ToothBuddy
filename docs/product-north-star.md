# ToothBuddy — Product North-Star

2026-05-29 重定义。这份文档是 ToothBuddy 的产品权威定义，取代旧的 `docs/feature-inventory.md` 以及 `ROADMAP.md` / `PLAN.md` / `specs/` 里"习惯打卡 / 家庭"那套旧定位。任何会话开始先读这份。

---

## 一句话定位

ToothBuddy 帮一个人**把每一次刷牙刷得更到位**——刷够时间、每个区都刷到——并把它变成一份**可验证、可给牙医看的口腔健康记录**。

不是"提醒你每天刷两次"。大部分人这个习惯已经有了；真正的痛点和差异化在**质量、时长，以及把它变成可证明的数据**。

---

## 我们解决的三个需求

1. **质量** —— 提示什么时候刷哪个区、每个区刷多久，确保覆盖到位。有摄像头就用摄像头确认，没有就用分区计时引导兜底。
2. **时长合规** —— 监督用户刷够牙医标准时间（默认 2 分钟，可设 3 分钟），不是刷个 30 秒就算。
3. **可验证记录 = 健康数据** —— 每次刷牙按时长 + 覆盖 log，长期累积成口腔健康数据，可离线导出给牙医，当问诊 / 依从性证据。

核心 use case：被牙医点名要好好刷牙的人（蛀牙反复的小孩、戴牙套的正畸患者、牙周病人），拿这份记录向牙医证明"我确实刷够了时间、刷到了每个区"。

## 我们不解决的

- 不做临床诊断、不替代牙医、不测菌斑。
- 不卖硬件、不连电动牙刷（软件 only，见 `product-scope-software-only` 记忆）。
- 不做"一家人共用一台手机轮流刷牙"——这个 use case 几乎不存在。

---

## 目标用户

主打**个人用户**：一台设备 = 一个人（机主）。小孩用家长手机的场景，按"这台手机是小孩的、小孩有独立账号"处理，不做"家长替小孩在同一台机上管多个档案"。

更锐的一类（接近刚需而非 vitamin）：**被牙医要求改善刷牙的人**。对这群人,"可验证的刷牙证明"是真需求。产品可以围着他们做定位收窄。

---

## 核心洞察：刷牙时为什么要打开我们的 app

这是整个产品最大的风险点——很多人刷牙根本不看手机，要么专心刷、要么刷手机打发时间。

**洞察：刷牙是每天固定 2 分钟、雷打不动、双手和眼睛半占用的时间槽。** 我们真正占的不是"刷牙工具"，是"这 2 分钟"。问题变成：这 2 分钟塞什么，值得用户打开。

**答案：audio-first 免手免眼教练。** app 说话不用你看——"现在左上……继续……换右上"，中间插一个 2 分钟的小东西（笑话 / 冷知识 / 今日一句）。手机搁台面甚至兜里都行。你不看手机？不用看，你听。它免手免眼带你刷得更到位、让 2 分钟不无聊，顺手把健康记录建起来。

愿意把手机架起来当镜子的用户，再给一个视觉富模式（智能镜）。

---

## 一次刷牙 session 长什么样

**脊柱 = 规定路线（prescribed route）。** app 驱动你走完一套结构化分区流程：每个区给目标时长，到点提示换下一个区，所有区刷够 = 达标。这套**不要摄像头也能 100% 跑全程**，正好是牙医推荐的系统化分区刷法。

三种呈现叠加：

- **B｜audio-first 免眼教练（底座，默认全员有）** —— 语音念分区引导 + 计时 + 中段内容。不需要看屏幕。
- **A｜智能镜（可选视觉富模式）** —— 把手机架起来：自拍画面 + 当前该刷的区高亮 + 进度 + 糖虫小游戏。给愿意看屏幕的人。
- **D｜结束总结（bookend）** —— 刷完给一份爽快的总结：哪些区刷到了 / 刷够了、总时长达标没、这次有没有摄像头佐证。

**相机当确认层，不是驱动层。** 规定路线驱动流程；摄像头开着时，Vision 确认你大致在对的一侧、提醒你别老在左边刷，并把"检测到的"每区 dwell 记成覆盖数据。

## 诚实边界（决定我们能 claim 什么）

手机前摄**测不了临床清洁质量**——刷头在嘴里、被手和泡沫遮挡，看不到牙龈线刷没刷到。能诚实测的只有：**哪一侧 / 哪个区、刷头在不在嘴边、刷了多久、在不在动。**

所以我们卖的"质量" = **覆盖（每个区刷到没 / 刷够没）+ 时长（够不够 2 分钟）+ 一致性（长期稳不稳）**。**不显示成一个"质量分"数字**（怕被误当临床指标，也怕诱导用户对着摄像头刷假动作刷分）。给牙医的是"今天 6 个区全刷到、2:15、达标 ✓"这种可辩护的事实，不是"质量 87 分"。

**verified-by-camera vs guided-only 标志（反作弊关键）：** 每条记录带这个标志。没开摄像头 / 没在镜头里检测到刷牙的 session，标成 guided-only ——牙医一眼能看出这条"没有视频佐证"。纯音频 / 无相机模式下，记录本质是"用户跟着跑完了结构化 2 分钟分区流程 + 时长"，不是"验证过每个区真刷到"；相机开着才升级成"检测确认的覆盖"。即便是 guided-only，"连续 30 天每天两次跟着做完结构化 2 分钟"对牙医也远超他现在手里的（现在是零）。

## Feature Map：现有功能逐条处置

### 保留（keep，可能小改适配新记录）
- 2 分钟 session 的计时 / 摄像头预览 / Vision 分区识别（`VisionFrameProcessor` / `BrushingZoneMonitor` / `ZoneGuidance`）——是新引擎的基础。
- Sugar Bugs 糖虫小游戏——从"kid 限定"改成"全员默认有、设置可关"，归入智能镜视觉模式。
- 刷牙时插入的笑话 / 冷知识 / tips（`ContentEngine` / `ContentSelector`）——audio-first 的内容来源。
- Live Activity / 灵动岛——管道保留，`zoneHint` 改成带分区进度。
- Siri / App Intents——管道保留；"开始刷牙 / 记录刷牙"逻辑不变；"我的 streak" 那条改成播报质量指标。
- HealthKit 写 `toothbrushingEvent`——保留；新模型下 `metMinimum` 让写入更有意义；授权入口从 adult-gated 改成全员可见。
- 宽容 streak（`StreakEngine`）——**保留但降级**（见下）。
- 自适应提醒 / 濒危提醒（`ReminderPlanner` / `NotificationScheduler`）——保留当留存工具。
- PDF 报告（`ReportBuilder` / `ReportPDFRenderer`）——**升级**成牙医证明（见下）。
- Onboarding——保留，去掉 kid/adult 选择，加一个引导用的"主要给谁用"预设（可选）。
- Duo 设计系统——保留；视觉精修延后。

### 改（change）
- **记录变厚** —— `BrushingRecord` / `CDBrushingRecord` 加：activeSeconds、分区覆盖 map、targetSeconds、metMinimum、cameraVerified、guidanceMode。
- **session 变结构化** —— 从"自由数秒到用户喊停"改成"规定路线 + 分区计时 + 真·达标 + 全程 audio 引导"。
- **奖励重指向** —— 从"按 session 数升级 + 打卡成就"改成"按质量 / 时长 / 达标 / 覆盖"。streak 不再绑奖励。
- **kid/adult 去硬分** —— 所有按 `mode` 分叉的行为（糖虫、内容 tone、星星/彩纸、等级卡、习惯曲线、成就区）改成设置里逐项 toggle，默认全开。
- **Widget 重指向** —— `WidgetSnapshot` 主角从 streak 数字改成今日质量状态（达标 / 覆盖），streak 降成小角标。
- **报告升级成牙医证明** —— 加每次时长 / 覆盖 / verified 标志 + 达标率，清楚标出哪些 session 有相机佐证。

### 删（delete，净删除）
- 多档案家庭整层：`GroupDashboardView` / `GroupStore` / `DashboardMetrics` / `CDGroup` + 关系 / Family tab / `allRecords()`。
- 多档案 UI：`ProfilePickerView` 的档案切换器 + 首启 gate + 创建时的 Kid/Adult 选择。
- 旧 JSON→CoreData 迁移代码（greenfield，无真实用户）。

### 新（new）
- **规定路线引擎**（Core 纯逻辑，扩 `SessionScript` + `GuidanceDecider`）：分区序列 + 每区目标时长 + 进度 + 达标判定。
- **Settings 界面**（全新）：逐项功能开关 + 目标时长（2/3 min）+ session 模式（audio / 智能镜）。
- **结束总结**重做：覆盖 map + 时长达标 + verified/guided 角标。
- **牙医证明离线导出**：升级的报告。

## 留存与奖励哲学

这是个 **vitamin app 不是 painkiller**——所以留存是生死线，也是最大摩擦（用户想不起来用、嫌麻烦）。但留存循环要重新瞄准：

- **两个分开的循环。**「记录一致性」（你今天刷了并记了吗）喂留存 / 提醒，是配角；「质量 + 时长」是英雄指标、健康记录、给牙医的东西，奖励围着它转。
- **streak 保留但降级** —— 从英雄指标退成温和的"别忘了记录"的留存提示。提醒功能的主要价值是提醒用户回来用 app 记录刷牙。
- **奖励绑质量** —— 庆祝"6 个区全刷到""刷够 2 分钟""有相机佐证的 session"，不庆祝单纯打卡。

## 分享

替代家庭层。先后两步：

- **Phase 1（先做，离线）：牙医证明。** 一份可导出的报告 / 链接，复诊时拿给牙医看。牙医不会订阅你的实时刷牙流，要的是这种点对点、正式、低频的东西。不依赖后端。
- **Phase 2（后做，联网）：朋友 / 家人社交。** 联网身份 + 双向实时可见（我分享我的刷牙记录给妈妈 / 朋友，互相看得到，单向或双向）。需要联网 + 后端 / CloudKit。

---

## Phase 切分

- **Phase 1（本地，不碰后端）：核心重做。** 质量 / 时长 / 可验证记录的新 session 内核 + 去 kid/adult 区分 + 砍多档案改单 profile + Settings 开关 + audio-first 规定路线 session + 智能镜模式 + 结束总结 + 牙医证明离线导出 + 重指向奖励 / Widget / Siri / HealthKit / Live Activity。详见 rebuild plan。
- **Phase 2（联网，勾勒不展开）：** 用户身份 / 账号、CloudKit 或自建后端、牙医分享链接、朋友 / 家人双向可见。

## 非目标（明确不做）

- 临床诊断 / 菌斑检测 / "质量分"数字。
- 硬件 / BLE / 电动牙刷集成。
- 一家人共用一台手机的多档案。
- App Store 上架推进——**已暂停**，等核心重做完再回头（旧的 listing / 截图 / 分类 / icon 的"家庭习惯"叙事都要重做）。
- 视觉精修 / 内容资产中文化——延后，现阶段能看能用即可。
