## 1. 背景与问题

ToothBuddy 已完成质量转向重做(Phase 1)+ 本地闭环打磨(Phase 1.5),核心是"刷牙时长 + 分区覆盖 + 可验证记录"。

但有一个被高估的前提被证伪了:**产品目前无法可靠地给刷牙"质量"打分**。代码核实结论:

- 有摄像头 + Vision 识别(`VisionFrameProcessor.swift`:人脸 landmark + 手部姿态 → 估算刷哪个象限),累计每区覆盖秒数,并给一个防作弊的 `cameraVerified` 标记。
- **没有**数字"质量分"。`BrushingRecord.starCount`(见 `ToothBuddyCore/Sources/ToothBuddyCore/BrushingRecord.swift`)纯看时长(≥2min=3★),`metMinimum` 是"每区达标 + 总时长达标"的 pass/fail。
- 这套分区识别是**引导级、非临床级**,且据 PROGRESS **从未真机验证**。测不了菌斑清除、力度、角度、真正干不干净。

**所以真正的难点不是"怎么打分",而是:在测不了质量的前提下,如何让用户(尤其小孩)每次刷牙都想打开 App。** 这份文档定义 v1 的留存引擎。

**调研依据(4 路市场调研,16+ app):** Finch、Pokémon Sleep/Smile、Neko Atsume、Tamagotchi、Duolingo、Streaks、Fabulous、Forest、Habitica、BeReal、Snapchat streaks、Strava、STEPN、亲子打卡类。四路高度收敛,结论见下。

---

## 2. 目标(Core outcome)

让"打开 ToothBuddy 刷牙"成为小孩每天早晚主动想做的事——驱动力来自**一个需要他们的角色(Buddy)**和**随时间攒起来、怕失去的东西**,而不是来自"刷得好不好"的评判。

**成功长这样:** 小孩早上会主动想看"Buddy 昨晚带回了什么",晚上会想"给 Buddy 收工";漏刷时是"Buddy 有点蔫,我下次补上",而不是"我失败了被惩罚"。

---

## 3. 主要用户与定调

- **设计重心:小孩优先**(家长购买、孩子使用)。v1 的情感基调与留存机制先为小孩调。
- **家长:队友,不是监工**。v1 只做**本地可见**(同设备上能看记录),远程提醒/分享推迟。
- **大人模式**:仍保留(设置开关),但 v1 用"同一套核心 + 更克制的皮肤/强度",不为大人单独设计新机制。
- **非用户 / 不服务:** 追求临床级刷牙质量评估的用户;想要竞技排行/社交攀比的用户。

---

## 4. 贯穿全局的设计原则(不可违背)

**P1 · 奖励只挂在"可验证的仪式完成",绝不挂在"质量/次数"。**
唯一能诚实验证的信号是"计时器真的跑满了 ~2 分钟"。所有奖励(streak、收集、Buddy 状态)都 gate 在它上面。绝不奖励"刷得多好"(测不准)或"刷得多"(一天固定 2 次,没有多做的空间)。
> 避坑:Finch 被用户诟病"不刷也点掉勾拿币";Pokémon Sleep 的魔法在于它能真测睡眠——我们没有这个,所以不能假装测质量。

**P2 · Buddy 是"依赖你的小生命",不是"头像/logo"。**
心理学核心:对自己食言容易,对一个需要你的小家伙食言难受。这比 streak 本身更黏。现有 `DuoCharacters.swift` 里的 Buddy 要从"静态品牌图"变成"会反应的伙伴"。

**P3 · 会难过,但绝不死、绝不永久惩罚。**
Tamagotchi 的"会 suffer 但能 recover"是甜点;permadeath/硬清零对小孩是焦虑源。漏刷 → Buddy 蔫;下次刷牙 → 满血复活。

**P4 · 温柔,不羞辱。**
无 confirm-shaming("你真的要放弃吗")、无罪疚式推送、无硬 streak 清零。断链是"Buddy 欢迎你回来",不是惩罚。

**P5 · 不碰的黑暗模式(小孩健康 app,硬红线):** 真钱抽卡/开箱、pay-to-save-streak、公开排行榜与同伴攀比、加密/代币奖励、FOMO 稀缺倒计时、近失(near-miss)诱导动画。

## 5. v1 需求(Requirements)

> 主轴 = 养成/隔夜循环(方案 A),**分期上**:v1 = 地基 + 从 A 拎出的"早上揭晓"魔法一下;完整探险/世界建造二期。奖励中枢:**每完成一次 2 分钟刷牙 = 铸一枚 "brush token"**,这枚 token 同时喂 streak、收集、Buddy 状态。

### R1 · 首页重建(去掉假质量分)
- 移除任何"质量分 88/92"式数字(它不存在)。
- 首页三块:**今天的两个环(早/晚)** + **Buddy 当前状态**(精神/蔫,可点)+ **收集进度**入口。
- 现有 `HistoryView` 的 streak 卡 / 成就 / 记录列表保留,但首页信息层级以 Buddy + 今日环为主角。

### R2 · 双环 streak(宽容模型)
- 一天有**两个目标环**:早、晚各一个。完成一次达标刷牙 → 闭合对应的环。两个都闭 = "完美的一天"。
- **day-streak(情感火焰):** 当天完成 ≥1 次达标刷牙即保住;`GamificationStore` 现有 streak 逻辑需按此调整(避免"漏一次炸全部")。
- **周目标:** 一周闭合 N/14 个环的进度条(具体阈值 planning 定,默认宽松)。
- **"病假"freeze("Buddy 帮你占着位"):** 漏刷日**自动**消耗一个 freeze 保住 streak;可攒 1–2 个,靠连续刷牙赚回。断链后是温柔的"回来"流程(P4),不是清零羞辱。
- 明确不做:leagues、排行榜、按次数/质量计的 streak。

### R3 · 隔夜循环 + 早上揭晓("魔法一下")
- **晚上刷牙 = 送 Buddy 出门 / 哄睡**:完成当天最后一次刷牙后,Buddy"出发过夜"。
- **早上刷牙 = 唤醒 + 揭晓**:新的一天第一次刷完,Buddy"回来了",带回**一个小惊喜**(一个收集物 / 一张涂鸦 / 一句话小故事)。
- 揭晓**gate 在早上那次刷牙的计时器跑满**(P1),不是"打开就领"。
- 这给一天两次固定 session **各自一个开 App 的理由**,解决"动作永远不变为什么还想开"。
- v1 揭晓内容是**一个小而有限、可扩充的起始集**(planning 定量),不做完整探险地图/多结局。

### R4 · Buddy 会反应(情感核心,单项最大工程)
- Buddy 从静态 Canvas 图变成**状态驱动**的伙伴,至少这些状态:
  - `idle`:待机呼吸循环(永不定格)
  - `cheer`:刷牙中达标/换区时弹跳、咧嘴
  - `celebrate`:刷完达标,跳起 + 星星
  - `dim/sad`:漏刷后蔫(可恢复)
  - `wake/return`:早上揭晓时登场
- 技术选型(更正见 §9):工程实为 Xcode `.xcodeproj`(2026-05-18 由 .swiftpm 迁移,`project.yml`),**Rive/Lottie 可用、并未被封死**。v1 仍**推荐手搓 SwiftUI**(分层视图 + `.phaseAnimator`,零依赖、5 个状态够用);Rive 作为手搓够不着时的升级后路,而非需要转工程的大动作。
- 复用点:`DuoCharacters.swift`(BuddyView/FoamView 等)。

### R5 · 轻收集
- 每完成一次刷牙 = 一次**变量小奖励**(贴纸 / 伙伴 / Buddy 世界的小物件),进一个"**大但有限**"的册子(Pokémon Smile 式图鉴)。
- 奖励节奏 = 保底一个 + 偶尔稀有(Habitica 式分层),给变量奖励的多巴胺,但**数量硬顶在仪式次数**(最多 ~2/天),grinding 不可能。
- v1 与 R3 揭晓共用同一套收集内容即可(揭晓 = 收集物的登场时刻)。

### R6 · 刷牙中百科(你的第 3 点)
- 把**已有的 100 条 fun facts**(现在多在 `BrushView` 准备阶段轮播)搬进**刷牙过程中**呈现,小孩趣味版语气。
- 大人模式给实用版(可复用 `TipsView` 内容源)。低成本,提升"刷牙过程"的生动度。

### R7 · 通知(留存的"召回"触发)
- 用 **Buddy 的口吻**("Buddy 在等你刷牙啦"),不是品牌口吻(Duolingo 实测吉祥物进通知 +5% DAU)。
- **按用户平时刷牙的时间点**触发(behavior-timed),不是固定死时刻。
- 两类分工:日常召回 vs streak 濒危挽救,文案不同。全部温柔、可关(P4)。

### R8 · 庆祝改造(你的第 4 点)
- 结束页去掉质量分;保留 **星星(来自时长,真实)+ 环闭合 + Buddy celebrate 动作 + 收集揭晓**。
- 按量级分级(proportional celebration):达标最低线 / 满 2min / 破纪录,彩带与 Buddy 动作强度递增(`DoneResultSheet` 现有 `metMinimum` 分支扩成多档)。

### R9 · 摄像头降级为可选引导
- 现有 Vision 分区识别(`VisionFrameProcessor` / `GuidedSessionEngine` / `cameraVerified`)**不再是奖励引擎**,退为"可选引导"(帮你知道刷哪块)。
- `cameraVerified` 记录字段保留(未来给牙医的"没造假"证据仍有价值),但 v1 的 streak/收集**不依赖它**。

## 6. 成功标准(Success criteria)

- **行为:** 小孩在早上首次刷牙前主动打开 App 看揭晓(定性:用户/家长反馈"孩子会想看 Buddy 带回什么")。
- **留存代理指标:** 早晚两次 session 的完成率;day-streak 中位长度;7 日留存(对标 Duolingo:7 日 streak 用户次日回访显著更高)。
- **情感:** 漏刷后的反应是"补上/心疼 Buddy"而非"失败/被罚"(定性)。
- **诚实性守恒:** 全程无任何界面声称或暗示"你刷得好/干净"(P1 自查)。
- **真机成立:** Buddy 反应动画 + session 环在真机上流畅、不掉帧(见风险)。

## 7. 范围边界

**推迟到二期(不是 v1):**
- 完整隔夜**探险内容**(地图/多结局/长篇故事);Buddy **世界建造与深度装扮系统**。
- **联网分享**:远程家长提醒、朋友/兄弟姐妹 brush-streak(Snapchat/Duolingo 式共在)、牙医在线看记录。均需账号/后端 = roadmap Phase 2。
- 大人模式的**独立机制**(v1 只做克制皮肤)。

**在此产品身份之外(不做):**
- 临床级质量评估 / 菌斑检测 / 力度打分。
- 竞技排行榜、公开攀比。
- 真钱抽卡/开箱、代币经济、pay-to-save-streak(P5)。

## 9. 风险与未知

- **R-1(最大)· Buddy 反应动画的可行性与质量。** 主轴 A 的情感钩子全压在这。**更正(2026-07-03 核实 `project.yml`/`PLAN.md`):工程早在 2026-05-18 就从 .swiftpm 迁到 Xcode `.xcodeproj`(XcodeGen),之前"禁 Rive/Lottie"的说法不成立——Rive 可直接加。** 路线:v1 先手搓 SwiftUI(零依赖、5 状态够用);若达不到"活"的门槛,直接加 Rive(无需转工程,只是多一个依赖 + 要在 Rive 编辑器做 `.riv` 资源;注意 Swift 6 strict + warnings-as-error 可能要处理 Rive runtime 的告警)。**需要一个早期手搓原型验证够不够——即当前这步。**
- **R-2 · 真机从未验证。** 整个产品(含分区识别、相机、时长计)据 PROGRESS 没真机跑过。留存引擎的所有体验(尤其动画、揭晓)必须真机验才算数。
- **R-3 · 收集内容的产能。** R3/R5 需要一批收集物美术;v1 靠"小而有限的起始集"控制,但要有出图能力或极简风格方案。
- **R-4 · 揭晓的"离线时间"逻辑。** 隔夜循环依赖"晚上→早上"的时间边界判定,要处理时区/熬夜/白天补刷等边角(planning 细化)。
